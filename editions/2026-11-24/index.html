Ruby's string bug is critical, so check your version before lunch

The Ruby team disclosed ruby2shell, a critical heap buffer overflow in how Ruby changes the case of strings, on November 19. Rails and classic-style Sinatra apps hit the bug in their default configuration, before any login screen, and proofs of concept exist that achieve remote code execution. Before you panic-upgrade, find out which Ruby your app actually resolves to.

What broke, and in plain words

A heap buffer overflow means a program writes past the end of a chunk of memory it was given, corrupting whatever was sitting next to it. In this case the trigger is something as boring as changing a string's case, so an attacker doesn't need a login to reach it: Veria Labs found that Ruby on Rails and classic-style Sinatra applications hit the bug in their default configuration, before any authentication. The flaw is tracked as CVE-2026-132825, rated Critical by the Ruby team, with a related integer overflow in the same string case-conversion code fixed in the same releases.

The fixed versions are Ruby 3.3.14, 3.4.13, and 4.0.10, so there is a patch available no matter which release line you're on. The awkward part is that self-hosted products bundling Ruby, including GitLab, Mastodon, Discourse, OpenProject, Chatwoot and GitHub Enterprise Server, shipped an affected Ruby in their latest release at the time of disclosure, so if you run any of those, the upgrade path goes through them, not just your own Gemfile.

Check your versions before you touch anything

The mistake everyone makes during a security scare is upgrading the thing they think they run instead of the thing they actually run. Ruby versions live in several places: the version pinned by your repository's toolchain files, the version your terminal resolves to right now, and the version your Rails and Bundler gems were installed against. They are not always the same, and the gap between them is exactly where memory bugs hide.

Run the example in the Run this block below against your own repository. It prints the Ruby, Rails and Bundler versions your repository resolves, plus the local toolchain versions. The observable output is a short table: if the Ruby line shows 3.3.14, 3.4.13, 4.0.10 or later, you're patched and can go back to your day. If it shows anything older, you have found your afternoon. Nothing is changed by the script; it only reports, so it's safe to run anywhere.

Patch first, then lean on the safety net

Cloudflare's web application firewall, a filter that sits in front of your app and blocks known attack patterns, now blocks ruby2shell for every customer including Free plans, with two new rules enabled by default and set to Block. That is a genuine safety net, and the WAF rule for the related PHP flaws updated earlier even caught part of this class of pattern before disclosure. But the source post is blunt about it: the WAF is a compensating control, not a replacement for patching, because exploits can reach the bug through paths a WAF cannot see.

So the order of operations is: run the version check, upgrade Ruby to a fixed release, and treat any firewall protection as the seatbelt you wear while the airbag gets installed. Your next concrete step is to run the check in your repository, note the Ruby line, and if it's stale, plan the upgrade before the proofs of concept become working exploit kits.

Why it matters

  • Default Rails and Sinatra apps reach this bug before authentication, so an unpatched app is exposed without needing a valid user.
  • Fixes exist on every maintained Ruby release line, so there's no excuse requiring a major-version jump.
  • Self-hosted tools like GitLab, Mastodon and Discourse bundled an affected Ruby, so the fix may be a product update rather than your own code.

Copy snippet

#!/usr/bin/env python3
"""Print the Ruby, Rails and Bundler versions a project actually runs."""
import pathlib
import platform
import shutil
import subprocess
import sys


def version(label, command):
    if not shutil.which(command):
        return f"  {label}: not found"
    try:
        result = subprocess.run([command, "--version"], capture_output=True, text=True, timeout=10)
        line = (result.stdout or result.stderr).strip().splitlines()[0]
        if "not currently installed" in line:
            return f"  {label}: not found"
        return f"  {label}: {line}"
    except Exception as exc:
        return f"  {label}: error ({type(exc).__name__})"


root = pathlib.Path(sys.argv[1] if len(sys.argv) > 1 else ".").resolve(strict=True)
print("project:")
for name in ("Gemfile", "Gemfile.lock"):
    print(f"  {name}: {'found' if (root / name).is_file() else 'absent'}")
lock = root / "Gemfile.lock"
if lock.is_file():
    lines = lock.read_text(errors="replace").splitlines()
    for number, line in enumerate(lines):
        text = line.strip()
        if text.startswith("rails ("):
            print(f"  rails: {text[7:-1]} (Gemfile.lock)")
        elif text == "RUBY VERSION" and number + 1 < len(lines):
            print(f"  ruby: {lines[number + 1].strip().removeprefix('ruby ').strip()} (Gemfile.lock)")

print("toolchain:")
print(f"  os: {platform.system()} {platform.release()} ({platform.machine()})")
for label, command in (("ruby", "ruby"), ("rails", "rails"), ("bundle", "bundle")):
    print(version(label, command))
