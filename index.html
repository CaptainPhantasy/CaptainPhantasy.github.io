Your laptop can run a coding model now, and the fallback is free

The local-model conversation has a hardware problem. Most guides assume a rack of GPUs or a 128 GB workstation. The models got smaller this year. A useful coding fallback now fits on a gaming laptop, and the only question that matters is how much memory you can give it.

November 24, 2026 4 min read Local AI

By Legacy AI

The models got small enough to matter

Three releases changed the size math this year. Prism ML's Ternary Bonsai 2 compresses a 27-billion-parameter Qwen model into a ternary build: 5.95 GB for the PTQ1_0 file and 7.21 GB for PQ2_0, while keeping about 98% of the base model's benchmark score. JetBrains' Mellum2.1 Thinking is a 12-billion-parameter mixture of experts with 2.5 billion active per token; its Q4_K_M build is 8.07 GB. Qwen3.8-27B is a dense 27-billion model with a 262K-token context, and a four-bit build lands around 17 GB.

The wider field is just as usable. OpenAI's gpt-oss-20b is a 21-billion mixture of experts that ships natively in MXFP4 at about 14 GB. Mistral's Devstral Small 2 is a 24-billion dense agentic coder at 12.76 GB in IQ4_XS or 14.33 GB at Q4_K_M. Qwen3-Coder-30B-A3B is an 18 GB four-bit build with 3.3 billion active parameters. Gemma 4's 26B-A4B mixture of experts is about 17 GB, and the 31B dense build is 18.32 GB. Most of these are Apache 2.0.

None of them is a frontier model. That is the trade. You give up the top of the benchmark table and the largest context windows for a model that costs nothing per token, runs without a network, and keeps your code on the machine. For a fallback, that is usually the right trade.

The only number that matters is memory

Parameter count is not memory. What has to fit is the weight file, the KV cache that grows with context, and the runtime's own overhead. The 31B Gemma looks comfortable on a 24 GB card at 18.32 GB, until you add the runtime and a 32K context: the KV cache alone is about 3.94 GB at 32K, which runs the total past the card. The same model that feels fine at 4K is unusable at 32K. Context is a budget, not a free setting.

The hardware splits into two kinds. A discrete GPU has its own VRAM; the model must fit there, or layers spill into system memory and speed collapses. Apple silicon shares one pool between CPU and GPU, so a 32 GB Mac is a 32 GB budget with the operating system on the same bill. Either way, leave two or three gigabytes for the desktop, the editor, and the context you actually want.

Quantization is the other dial. A four-bit file is roughly a quarter of the 16-bit size, and the quality loss is usually small; a ternary build goes further. Smaller is not always better: a two-bit build of a large model can lose more than a four-bit build of a smaller one. Pick the largest file that fits with a couple of gigabytes left over, then shorten the context before you shrink the model.

Set up the fallback, then test it like a tool

Start with a runtime, not a model. Ollama is the shortest path; llama.cpp gives you more control; LM Studio is the GUI. Pull one of the smaller builds first, either Bonsai 2 or Mellum2.1, and run a real task from your own work. Ask it to explain a function in your repository, write a test for a bug you already fixed, or review a diff. Do not judge it on a riddle.

Measure what you got. Note the tokens per second, the time to the first token, and whether the fan or battery makes the experience unpleasant. Then wire it into your editor as a fallback provider and test the failure path: turn off the network, switch to the local model, and finish one small task. A fallback you have never used is not a fallback.

Keep the cloud model as the primary and the local one as the seatbelt. Use the local model for private code, offline work, rate-limit days, and the tasks where a slightly weaker answer is fine. Do not pretend it is the same model. The value is that it is yours, it is free, and it still works when the API does not.

#!/usr/bin/env python3
"""Report memory, GPU and local-model tools, and which models fit. Read-only."""
import pathlib
import platform
import re
import shutil
import subprocess
import sys


def shell(args):
    try:
        return subprocess.run(args, capture_output=True, text=True, timeout=10).stdout.strip()
    except Exception:
        return ""


def memory_gb():
    if sys.platform == "darwin":
        raw = shell(["sysctl", "-n", "hw.memsize"])
        return round(int(raw) / 1024**3) if raw.isdigit() else 0
    if sys.platform.startswith("linux"):
        try:
            for line in pathlib.Path("/proc/meminfo").read_text().splitlines():
                if line.startswith("MemTotal:"):
                    return round(int(line.split()[1]) / 1024 / 1024)
        except OSError:
            pass
    if sys.platform.startswith("win"):
        raw = shell(["powershell", "-NoProfile", "-Command",
                     "(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory"])
        return round(int(raw) / 1024**3) if raw.isdigit() else 0
    return 0


def gpu_line():
    if sys.platform == "darwin":
        text = shell(["system_profiler", "SPDisplaysDataType"])
        chip = re.search(r"Chipset Model:\s*(.+)", text)
        cores = re.search(r"Total Number of Cores:\s*(\d+)", text)
        vram = re.search(r"VRAM \(Total\):\s*(.+)", text)
        name = chip.group(1).strip() if chip else "not detected"
        if "Apple" in name:
            return name + (f", {cores.group(1)} GPU cores" if cores else "") + " (unified memory)"
        return name + (f", {vram.group(1).strip()} VRAM" if vram else "")
    if shutil.which("nvidia-smi"):
        out = shell(["nvidia-smi", "--query-gpu=name,memory.total", "--format=csv,noheader"])
        if out:
            return out.splitlines()[0].strip()
    if sys.platform.startswith("win"):
        out = shell(["powershell", "-NoProfile", "-Command",
                     "Get-CimInstance Win32_VideoController | Select-Object -First 1 -ExpandProperty Name"])
        if out:
            return out.splitlines()[0].strip()
    return "not detected"


MODELS = [
    ("Ternary Bonsai 2 27B", "PTQ1_0", 5.95),
    ("Ternary Bonsai 2 27B", "PQ2_0", 7.21),
    ("Mellum2.1 Thinking", "Q4_K_M", 8.07),
    ("Devstral Small 2 24B", "IQ4_XS", 12.76),
    ("gpt-oss-20b", "MXFP4", 13.8),
    ("Devstral Small 2 24B", "Q4_K_M", 14.33),
    ("Gemma 4 26B-A4B", "Q4_K_M", 16.95),
    ("Qwen3.8-27B", "Q4_K_M", 17.0),
    ("Qwen3-Coder-30B-A3B", "Q4_K_M", 18.0),
    ("Gemma 4 31B", "Q4_K_M", 18.32),
]

print(f"os: {platform.system()} {platform.release()} ({platform.machine()})")
gpu = gpu_line()
memory = memory_gb()
shared = "Apple" in gpu and sys.platform == "darwin"
print(f"memory: {memory} GB total" + (" (shared by CPU and GPU)" if shared else ""))
print(f"gpu: {gpu}")
print(f"disk free: {shutil.disk_usage(pathlib.Path.home()).free / 1024**3:.0f} GB")
print("tools:")
for label, names in (("ollama", ("ollama",)), ("llama-cli", ("llama-cli",)), ("lm studio", ("lms",))):
    print(f"  {label}: {'found' if any(shutil.which(name) for name in names) else 'not found'}")

print(f"models at {memory} GB, 2 GB runtime + 2 GB context reserve:")
fit = 0
for name, quant, weights in MODELS:
    need = weights + 4
    if memory >= need + 3:
        verdict = "fits with room"
        fit += 1
    elif memory >= need:
        verdict = "tight"
        fit += 1
    else:
        verdict = "won't fit"
    if name == "Gemma 4 31B" and verdict == "tight":
        verdict = "tight; only a short context fits"
    print(f"  {name} {quant} ({weights:g} GB): {verdict}")
print(f"summary: {fit} of {len(MODELS)} fit at a medium context; the largest need a shorter context.")
print("note: sizes vary by quantization. Apple silicon shares memory; a discrete GPU needs the model in VRAM.")
print("This is a memory check, not a speed benchmark. Nothing is downloaded or changed.")
