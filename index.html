ruby2shell can corrupt memory in a default Rails app before login

On November nineteenth, the Ruby team disclosed a heap buffer overflow in how Ruby changes the case of strings, rated Critical, with proof-of-concept exploits that achieve remote code execution in some scenarios. Fixes shipped in Ruby three point three point fourteen, three point four point thirteen, and four point oh point ten. The uncomfortable part: a default Rails or Sinatra app can reach the bug before anyone logs in, so step one is confirming which Ruby your own repository resolves today.

What ruby2shell actually is

A heap buffer overflow means a program writes past the end of a chunk of memory it was given. Attackers who can trigger that reliably can corrupt adjacent memory and, in the worst case, get the machine to run their own instructions. That's why 'Critical' and 'remote code execution' are sitting in the same sentence, and why proofs of concept already exist. In a language whose whole selling point is pleasant string handling, the bug living in case conversion is an especially cruel joke.

The reach is wider than Ruby apps you wrote yourself. Veria Labs found that Rails and classic-style Sinatra applications hit the bug in their default configuration, before any authentication. Self-hosted products that bundle Ruby, including GitLab, Mastodon, Discourse, OpenProject, Chatwoot and GitHub Enterprise Server, shipped an affected Ruby in their latest release at the time of disclosure. There's also a related integer overflow in the same string case conversion code, tracked separately, fixed in the same releases. Two bugs, one root cause, one upgrade.

Cloudflare's Web Application Firewall, a filter that sits in front of your site and blocks malicious traffic, now blocks ruby2shell for every customer including Free plans, with Block as the default action. But they say it plainly themselves: the WAF is a compensating control, not a replacement for patching, because exploits can reach the bug through paths a WAF never sees. The fix is upgrading Ruby. Everything else is a seatbelt.

Find the Ruby your app actually runs

The trap in Ruby version management is the gap between the Ruby you think you're on and the Ruby your app resolves. Your repository pins a version in its lockfiles and version files, your terminal has whatever your version manager last installed, and production has whatever the image baked in months ago. Those are three different numbers wearing the same name badge. Before you upgrade anything, print all of them in one place.

The runnable example in this edition does exactly that, against your own repository. It reads the Ruby, Rails and Bundler versions your repository resolves from its own configuration files, then reports the versions from the local toolchain as well. You'll see something like: your repo wants one version, your local interpreter is another, and Bundler, the dependency manager that installs your gems, is a third. If the resolved Ruby is anything below three point three point fourteen, three point four point thirteen, or four point oh point ten, you're looking at the bug, not at a rumor of it.

The observable output is a short report, not a diff. It changes nothing. That matters, because the instinct during a security scare is to start typing upgrade commands immediately, and the actual first skill is knowing what state you're in. Once you have the resolved versions, you bump the pinned Ruby in your repo's version file, run your test suite, and let the version manager install the patched release. For self-hosted bundles like Discourse or Mastodon, watch for their patched releases rather than swapping the bundled Ruby yourself, since that's the vendor's plumbing, not yours.

What to do before lunch

Run the version check against any Ruby project you touch, today, before you decide it's somebody else's emergency. If the numbers say you're affected, upgrade Ruby to a fixed release and then confirm your framework and gems still resolve cleanly, since a Ruby major-version jump can drag incompatible dependencies along with it. Rails and Sinatra apps on default configs are first in line because the bug is reachable pre-authentication, but any Ruby service in memory near untrusted input deserves the same five minutes.

If you sit behind Cloudflare, the WAF rules are already blocking, including on Free plans, so you have a bridge while the upgrade lands. Just don't confuse the bridge with the far shore: the Ruby team is aware of working proofs of concept, and a filter that never sees a request can't block it. Patch the runtime, keep the seatbelt, and get back to your Friday.

Why it matters

  • Default Rails and Sinatra apps reach the bug before any login, so a patched runtime is not optional diligence.
  • Self-hosted products like GitLab, Discourse and Mastodon shipped an affected Ruby in their latest release, so your stack may carry the bug through a dependency you never chose.
  • The versions your repo resolves, your shell reports and production runs can all differ; checking them in one place turns a guessing game into a five-minute task.

Copy snippet

#!/usr/bin/env python3
"""Print the Ruby, Rails and Bundler versions a project actually runs."""
import pathlib
import platform
import shutil
import subprocess
import sys


def version(label, command):
    if not shutil.which(command):
        return f"  {label}: not found"
    try:
        result = subprocess.run([command, "--version"], capture_output=True, text=True, timeout=10)
        line = (result.stdout or result.stderr).strip().splitlines()[0]
        if "not currently installed" in line:
            return f"  {label}: not found"
        return f"  {label}: {line}"
    except Exception as exc:
        return f"  {label}: error ({type(exc).__name__})"


root = pathlib.Path(sys.argv[1] if len(sys.argv) > 1 else ".").resolve(strict=True)
print("project:")
for name in ("Gemfile", "Gemfile.lock"):
    print(f"  {name}: {'found' if (root / name).is_file() else 'absent'}")
lock = root / "Gemfile.lock"
if lock.is_file():
    lines = lock.read_text(errors="replace").splitlines()
    for number, line in enumerate(lines):
        text = line.strip()
        if text.startswith("rails ("):
            print(f"  rails: {text[7:-1]} (Gemfile.lock)")
        elif text == "RUBY VERSION" and number + 1 < len(lines):
            print(f"  ruby: {lines[number + 1].strip().removeprefix('ruby ').strip()} (Gemfile.lock)")

print("toolchain:")
print(f"  os: {platform.system()} {platform.release()} ({platform.machine()})")
for label, command in (("ruby", "ruby"), ("rails", "rails"), ("bundle", "bundle")):
    print(version(label, command))
