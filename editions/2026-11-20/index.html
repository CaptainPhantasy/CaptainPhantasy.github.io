GitHub's new PR overview stops optional checks from crying wolf

GitHub's public-preview pull request Overview page got a round of fixes, and the headline is honesty: failed optional checks no longer make mergeable PRs look blocked. Interfaces that cry wolf get ignored, so this matters. Today you'll run a small scan to find the places your own workflows interrogate pull requests.

What actually changed

The Overview page has been in public preview since November 5, 2026, and this update answers the loudest feedback. The big one is merge status: failed optional checks used to make a mergeable pull request appear blocked, and missing merge requirements now show what needs attention. A readiness summary tells reviewers and visitors what to do, including when the correct answer is nothing, which is a refreshing break from a status page radiating vague disapproval.

The rest is polish with real payoff. Checks and approvals expand when clicked instead of pinning a preview; resolved review threads collapse so finished arguments stop haunting the scroll; force-push activity links to both the old and new commits, so reviewers can compare instead of trusting your promise that it was just a rebase. Commit activity now carries timestamps. You can join the preview with the Try the Overview page button in the header, and the same menu returns you to the classic view when you get nostalgic.

Find the automation that stares at your PRs

The Overview page reports merge readiness; a local scan answers a different question about automation. Use the narrow, read-only scanner supplied with this edition as a starting point, not as a merge-rules audit. Run it on your own repository: python3 find-pr-checks.py /path/to/your/repo. The script walks your workflow files and reports lines that query a pull request or a run through the GitHub CLI, like a step calling gh pr view.

In a local one-workflow fixture, the output looked like this: the review workflow at line four contained a gh pr view call, with one candidate line total. Your output will differ, since filenames, line numbers, and counts depend on your repository. Be clear about what this is: it does not enumerate your checks, your required statuses, or your merge rules, and a match proves nothing about gating behavior or preview access. It is a list of places to read, not an audit, and it executes nothing from your repository. Think of it as a flashlight, not a verdict.

Read the matches, then decide separately

For each matching line, open the step around it and read what it actually does with the pull request data. The required-versus-optional question is a separate manual review: it lives in your repository's settings, not in this scan, so go look there before concluding anything gates a merge. One matching line is a reason to ask a question, not a reason to rewrite a workflow before lunch.

Then flip on the preview, open your next pull request, and see whether the readiness summary matches what you found by hand. GitHub explicitly calls this preview a starting point and asks what still sends you back to the classic overview. If you have read your automation and your settings, you will have an answer worth sharing in the feedback discussion, which beats the usual feedback of quietly grumbling and closing the tab.

Why it matters

  • Failed optional checks no longer make mergeable PRs look blocked, so the page can distinguish a failed check from a missing merge requirement.
  • Force-push activity now links to both the old and new commits, meaning reviewers can verify your rebase instead of performing faith.
  • The preview is opt-in and reversible from the header menu, so auditing your PR-touching automation costs nothing but the coffee you were going to drink anyway.

Copy snippet

#!/usr/bin/env python3
"""List workflow lines that may be polling GitHub. Local, read-only; no CLI login."""
import argparse
import pathlib
import re

CHECK = re.compile(r'\bgh\s+(?:pr\s+(?:view|checks)|run\s+(?:view|watch))\b')


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('repository', type=pathlib.Path)
    root = parser.parse_args().repository.resolve(strict=True)
    workflows = root / '.github' / 'workflows'
    hits = 0
    for path in sorted(workflows.glob('*')):
        if (path.suffix.lower() not in ('.yml', '.yaml') or not path.is_file() or
                not path.resolve().is_relative_to(root) or path.stat().st_size > 1_000_000):
            continue
        for number, line in enumerate(path.read_text(errors='replace').splitlines(), 1):
            if not line.lstrip().startswith('#') and (match := CHECK.search(line)):
                print(f'{path.relative_to(root)}:{number}: {match.group()}')
                hits += 1
    print(f'candidate lines: {hits}')


if __name__ == '__main__':
    main()
